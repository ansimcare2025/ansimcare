돌봄지음 — 완전 분리 인증 시험용 브랜치 패치 (dolbom-auth-test)

이 파일은 기존 돌봄지음 v2.9.3에 덮어씌워 사용하는 독립 시험용입니다.
오직 신규 브랜치 dolbom-auth-test에만 올리고 운영 브랜치/사이트에는 올리지 마세요.

[구조]
* 웹 Firebase SDK: dolbomjieum-test
* 서버 Firebase Admin: 오직 dolbomjieum-test 서비스 계정 JSON만 허용
* 기본 쓰기 차단: CI_TEST_WRITES=enabled 전에는 기관 신청·승인 등 쓰기 불가
* 카카오: 전용 시험 사이트 도메인과 정확히 일치하는 복귀 주소만 허용
* Netlify: 기존 careindex-honam 프로젝트에 환경변수를 변경하지 말고 별도 사이트를 만드세요.

[새 Netlify 사이트를 만든 후에만 설정할 환경변수]
CI_DEPLOY_KIND = auth-test
CI_FIREBASE_PROJECT_ID = dolbomjieum-test
CI_TEST_WRITES = (처음에는 미설정 / 서버 연결 성공 후 enabled)
CI_ADMIN_UIDS = kakao:5193382364
FIREBASE_SERVICE_ACCOUNT_JSON = 새 시험 Firebase 프로젝트의 서비스 계정 JSON (비밀; GitHub 업로드 금지)
KAKAO_REST_API_KEY = Kakao Developers에 등록된 앱 REST API 키 (환경변수만)
KAKAO_CLIENT_SECRET = 사용하는 앱에 설정되어 있는 경우에만 (비밀)
KAKAO_REDIRECT_URI = https://<새-Netlify-사이트주소>/.netlify/functions/kakao-callback
FIREBASE_STORAGE_BUCKET = dolbomjieum-test.firebasestorage.app

주의: KAKAO_REDIRECT_URI는 Kakao Developers에서도 동일하게 등록하고 카카오 앱의 Web 플랫폼 도메인도 설정해야 합니다.
로그인 전 새 Firebase Authentication과 사이트 서버가 연결되도록 별도 설정/검증이 필요합니다.
이 패치는 실제 로그인 성공 및 승인 저장까지 검증한 배포본은 아닙니다.
비밀키는 채팅/깃허브에 올리지 마세요. 기존 운영용 서비스 계정 JSON을 복사해 사용하면 서버가 거부하게 되어 있습니다.

[권한 시험 순서]
1) 분리 테스트 사이트 접속 / 일반 로그인
2) 시험 Firebase의 대상 사용자에게 role=admin (관리자 UID) 권한 등록
3) 가상 요양원 생성
4) 기관담당자 신청/관리자 승인 / 해당 기관 이외 접근 불가 확인
5) 제출/수정 요청 → 관리자 확정 게시 시험
6) 종료 후 가상 기관과 시험 데이터 정리
