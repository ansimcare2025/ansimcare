# 케어인덱스 호남 v2.0 — 배포 전 서버연동 패키지

## 가장 중요한 안내
이 패키지는 **코드 구현 및 로컬 테스트용**입니다. Firebase 서비스 계정 비밀키와 카카오 REST API 키가 아직 입력되지 않았으므로 실제 카카오 로그인·실사용자 데이터·결제는 연결되지 않았습니다. 운영 도메인에서 실계정 통합테스트와 법적·개인정보·광고표시 검토가 필요합니다. 설치만으로 운영이 자동 개시되거나 98% 완료를 보증하는 것은 아닙니다.

## 구현 범위
- 기존 v1.9 디자인 재구성(모바일/PC), 보호자 검색 / 돌봄 질문 정리 / 보호자 관찰메모
- 카카오 OAuth REST 인증코드 → Netlify Function 서버 교환 → Firebase 커스텀 토큰 로그인
- Firebase 이메일 계정 로그인·비밀번호 재설정
- Firebase Admin SDK 관리자/기관 담당자 역할 및 기관 ID 연결
- 관리자의 기관 신규·수정 등록, 과거 CSV 비공개 가져오기, 기관목록 CSV 백업
- 기관 담당자가 정보·사진 변경 신청 → 관리자 승인·반려
- 입금 확정(수기)·게시 승인·계약기간 4중 조건을 만족한 유료기관만 보호자 검색에 노출
- 42개 권역(전주시 완산/덕진구 각각) × 4유형 홍보 정원 동시 계약 수 제한; 공개 잔여자리 조회
- 월 홍보료(방문돌봄 10만 / 주야간 15만 / 요양원 20만 / 요양병원 30만)
- 의료·돌봄 기관의 유료 광고라는 사실 명시(공적 인증/우수성 주장하지 않음)

## 설정 절차 — 관리자와 개발자 협업 필요
1. **원본 백업**: GitHub 기존 `index.html` 및 Netlify 배포, Firebase DB·규칙을 먼저 백업하세요. 파일을 바로 덮어쓰지 마세요.
2. Firebase 콘솔에서 `ansimcare-9bae3` 프로젝트를 확인하세요. 이 프로젝트가 운영에 적합하지 않다면 **새 Firebase 프로젝트를 만들고 `config.js` 및 `core.mjs`의 프로젝트 ID 제한을 변경**하세요. 기존 데이터가 그대로 이관되지는 않습니다.
3. Firebase Authentication에서 이메일/비밀번호 인증을 활성화하고 **승인된 도메인**에 Netlify 실제 도메인을 추가하세요. Firestore 및 Storage 버킷 활성화·접근 정책을 별도로 검토하세요. 사용자의 건강정보/민감정보를 수집하지 않는 현재 설계를 유지하세요.
4. Firebase 프로젝트의 서비스 계정 비밀키는 **Netlify 환경변수(`FIREBASE_SERVICE_ACCOUNT_JSON`)에만** 등록합니다. 업로드 ZIP, GitHub, 공개 사이트의 파일에는 절대로 넣지 마세요. JSON을 한 줄 전체로 복사하세요.
5. 카카오디벨로퍼스에서 앱의 **REST API 키**를 확인하고 카카오 로그인 활성화 및 Redirect URI를 정확히 등록하세요. 예: `https://실제도메인/.netlify/functions/kakao-callback` (경로·https 필수). 카카오 앱 설정에 필요한 사이트 도메인도 등록하세요. `KAKAO_REST_API_KEY`, `KAKAO_REDIRECT_URI`, 클라이언트 시크릿을 사용 중이면 `KAKAO_CLIENT_SECRET`을 Netlify 환경변수(Functions 범위)에 입력하세요. `config.js`에 카카오 REST API 비밀키를 넣으면 안 됩니다.
6. Netlify에서 **GitHub 저장소를 연결하여** 이 폴더를 배포하세요. **중요: Netlify Drop에 ZIP/HTML을 드래그하는 정적 배포만으로는 서버 Functions와 npm 패키지가 연결되지 않을 수 있습니다.** 서버 연동 배포를 수행하세요. Node 20+ 환경을 사용합니다. 배포 후 Functions 로그에서 오류를 점검합니다.
7. 첫 운영자 계정은 카카오로 로그인하거나 Firebase Authentication에서 이메일 가입 후, 화면에 표시된 UID를 확인하세요. 서비스 계정 키가 들어 있는 **신뢰할 수 있는 로컬 터미널에서만** `ADMIN_UID=... FIREBASE_SERVICE_ACCOUNT_JSON='...' node scripts/bootstrap-admin.cjs`를 한 번 실행하여 권한을 발급합니다. 그 뒤 로그아웃/로그인하여 관리자 화면을 확인하세요.
8. `firebase/CI_RULES_MERGE_ONLY.txt`의 안내대로 **기존 규칙은 보존하면서** ci_*에 대한 클라이언트 직접 접근 차단 규칙을 병합합니다. Storage도 별도 권한 검토가 필요합니다. 직접 Firebase Console에서 변경 전후 권한을 점검하세요.
9. 관리자로 비공개 기관 후보를 수입합니다. `관리자자료/과거_요양병원205_비공개이관.csv`는 과거 목록(2026-04)으로 개폐업·주소·전화·관할 구의 최신성을 반드시 재검증해야 합니다. 이 CSV 자체는 **공개 사이트에 업로드하지 말고 개인 PC에서 관리자 화면을 통해 가져오세요.**
10. 승인된 실기관에 대해 기관 정보 검증 → 기관 UID 연결 → 관리자 게시 승인 → **실입금 확인** → 시작일/종료일 등록·계약 활성화 → 익명 브라우저에서 유료 참여기관만 보이는지 검증하세요. 미래 시작 계약은 시작일 당일 활성화해야 하며, 지난 계약은 날짜 비교로 자동 숨김 처리됩니다.

## 보안·운영 주의
- 관리자 권한은 프런트엔드 메뉴가 아니라 Firebase Admin verified ID token/Custom claims로 서버가 검사합니다.
- **절대로** 서비스 계정 JSON, 이메일 임시 비밀번호, 어르신의 개인·건강정보, 이용자 개인정보를 CSV나 공개 배포 파일에 포함하지 마세요.
- 광고 계약 사실과 품질/안전성 검증은 별개입니다. 유료 목록은 해당 지역 전체 요양기관의 명부가 아닙니다. 광고 표시와 계약서·환불규정·사업자정보·개인정보처리방침·법률 검토가 필요합니다.
- 요양병원 의료광고에 해당하는 문구·표현은 실제 게시 전 관련 규제 및 심의 필요 여부를 확인해야 합니다.
- **결제사는 연결하지 않았습니다.** 현재 입금은 운영자가 수기로 확인·확정합니다.
- 계약 수납상태와 게시권한 변경은 Firebase DB에 기록됩니다. 별도의 회계·세금계산서 발행과 정기 백업 정책은 운영자가 마련해야 합니다.
- 고속 검색과 대량 처리: 공통 공개 목록 조회는 2,500개까지 동작하도록 구성했습니다. 공개 광고가 많아지면 검색 색인/페이지네이션을 개선해야 합니다.
- `npm test`: 권역·정원·노출정책 테스트, `npm run check`: 구문 검사. Firebase 서버/카카오 실로그인은 외부 비밀키·서비스 없이는 테스트하지 못합니다.

## 화면에서 보기
`site/index.html`이 사이트 시작 파일입니다. `site/design.css`, `site/v2.css`, `site/app.js`, `site/config.js`, `netlify/functions` 폴더가 함께 필요합니다. Netlify는 `site/`만 공개하여 서버 코드·원본 후보 데이터가 사이트 주소로 노출되지 않도록 설정합니다. 개발자 없이 `index.html`만 올리면 실제 로그인은 작동하지 않습니다.
